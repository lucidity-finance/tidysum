# 0004: The product is called Tidysum

Date: 2026-10-31
Status: accepted (the owner: "Purser is actually a very confusing name. Like, I keep reading it
Pursuer." He then picked Tidysum from a researched shortlist.)

## Decision

The product was called Purser until 2026-10-31 and is now Tidysum. "Tidy" is money in good order;
"a tidy sum" is a good amount of money. Together they say what the misallocation loop (0003) does
and what the user gets from it. The shortlist, the names that were cut and why, and the domain
checks were done in a separate naming study.

Everything says Tidysum: docs, the admin page, the CLI (`pnpm tidysum`), the MCP server name,
Plaid Link's client name, the launchd agent (`com.tidysum.serve`), the `TIDYSUM_*` environment
variables, the database and its roles, the CI runner and the repository.

## Internal names follow

A first pass (PR #22) renamed what users see and kept the old spelling on names that hold data.
The owner then asked for the old name to be gone everywhere, so a second pass renamed those too:

- The Postgres database, login user and Docker volume are `tidysum` and `tidysum-pg`. The Compose
  project is named `tidysum` in `docker-compose.yml`, so it no longer depends on the folder name.
- The agent roles, their session setting and the row-level security helper are `tidysum_agent`,
  `tidysum_proposer`, `tidysum.user_id` and `tidysum_session_user()`. Migration 0014 renames them in
  place; earlier migrations still create them under the old names, because applied migrations
  never change.
- The self-hosted CI runner was named `tidysum-ci`, and the GitHub repository is `tidysum`. CI has
  since moved to GitHub-hosted runners because this repository is public.

The one-time move of an existing install (renaming the database and its owner inside the old
container, copying the old volume into `tidysum-pg`, moving the checkout) was done by hand on the
operator's Mac after a `pg_dump` backup, not by a script in this repo.
